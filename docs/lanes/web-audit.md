# web-audit — public surfaces, judged cold

**Verdict: no fakes found — every number on every surface traces to a live field.** Two real bugs: `/city`'s "ledger, today" renders the last populated donation day (Oct 5) under a "today" label, and donation truth disagrees across surfaces (community says 22 trips, city/admin say 39). Plus hardcoded station dots on /city's minimap and a design-law nit list.

- Audited 2026-10-07 ~00:20–01:00 UTC against prod `http://alive108-2699c171ddded465.elb.ap-south-1.amazonaws.com` (GET only; admin audited as guest — `/admin/api/*` → 401 by design).
- Deploy rolled mid-audit: `ce01ec5c` → `a5005d4f` → `bc8f82c4` inside ~40 min. As of `bc8f82c4` the four surfaces serve **HEAD `0f5f879`** byte-for-byte (landing/city/admin diffed identical; `/community` serves HTML only to `text/html` clients). Everything below was re-verified against the live build after the roll; where the pre-roll page differed (old landing hero, pre-fix admin) it's noted as already shipped.
- Lane context: builds on `admin-deep-report.md` (its 16 guest-view fixes are now live on prod — verified: anonymized phones, dpcc row, public fallbacks all present). `truth-audit.md` covers the endpoint claims ledger — this audit is the surface side: what the pages do with those numbers. `judge-attack-audit.md` already owns the empty-citizen-layer framing; this adds the rendering bugs that make it look worse.

## The one-paragraph story for whoever fixes

`/city`'s "today" ledger is the only thing on the public web that will lie on demo day — it reads `days[lastKey]` instead of today's key, so Oct 5's 8 trips/38 km will sit under "TODAY" labels all week unless donations land. Right behind it: `/community` says 22 all-time trips while `/city` and `/admin` say 39 (two stores disagreeing), and the `/city` minimap shows 28 fixed dots next to a "54 live instruments" claim. Everything else is either live-true or honestly-empty.
