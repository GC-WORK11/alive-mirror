## Security and unverified notes — not exploit findings

- **Broad CORS is verified:** `server/main.py:234` permits `*` origins/methods/headers; GET `/health` with `Origin: https://audit.invalid` returned `Access-Control-Allow-Origin: *`. That does **not** prove a cookie-auth bypass or unauthorized mutation. No preflight/write/exploit probe was sent. Recommend narrowing trusted browser origins after checking the intended public API contract; do not change security policy to bypass any gate.
- Pattern scan of tracked `Mobile/` and `server/` source/config found no AWS access-ID literals, private-key PEMs, GitHub-token literals, Google-key literals, or literal admin-password assignments in the checked production paths. This is bounded source inspection, **not** compiled-APK secret certification or a comprehensive secret scan.
- CO₂ component mismatch proves retained aggregate inconsistency, not authorization to reset it or an audit of every user's underlying record. Privacy boundaries were respected; no per-device ledger rows were fetched.
- The unqualified GPS caption can still use the boot path's old last-known fix (F1's new guard protects personal storage only). A fresh-install UI/location-timing claim needs the actual build and rig.
- Decorative landing motes/boot digit noise use randomness (`landing.html:1419–1420,2523–2527`), but the metric resolves from `/v2/city`. Do not conflate decorative coordinates/digits with seeded air measurements. No claim of real particle trajectories is validated here.
- Python 3.12 was present but `pytest` was not installed. No dependency install or server test run was attempted for this mobile/report-only patch; production server integrator parity is not newly certified. No native build was justified under the existing-rig-only spot-check scope.
