# docs/ — what's where

This folder is big (~240 files) because the project was built by parallel
lanes, each of which left an audit trail. Read it in this order:

## Lane reports (`lanes/`, ~160 files)

Dated work receipts: every audit lane, fix lane, and test-day run writes a
report here — what was checked, what broke, before/after evidence
(screenshots live alongside in `lanes/*-shots/`). Naming: the `*-report.md`
file is the result; a bare `*.md` of the same name is usually the brief.
These are raw working documents — useful when you want to know *why*
something is the way it is; `plan/` is the cleaner read for *what* is.

## Numbered docs (`00`–`33`)

Product/research docs in roughly chronological order — early theses and
competitive research through design language, win analysis, and v2 load
testing. They explain reasoning; where they disagree with `plan/` or the
running service, the running service wins.
